# Contributing

Preserve the assurance contract before adding convenience. A patch must identify the source it changes, the property it intends to preserve, its explicit bounds, its failure behavior and its reproducible evidence.

- Keep consequential authority outside Python adapters. Decoding does not grant authority.
- Preserve original tests, accepted fixtures, source pins, recorded failures and proof obligations. Add new epochs rather than editing sealed evidence.
- Keep assurance-critical control flow nonrecursive and bounded. Use narrow types and contracts, short single-purpose functions, checked errors and strict warnings.
- Derive manifests from file bytes. Run the corresponding `--check`; never hand-edit a hash to make a gate pass.
- Record TESTED, OBSERVED, PROVED, ASSUMED, UNPROVEN, FAILED and UNPERFORMED accurately. Passing structure checks do not prove interpretation.
- Keep fixes and reviewable receipts together. Avoid unrelated formatting, dependency or architecture changes.
- Never commit private transported material, credentials, raw session traces or generated build caches.

The source inventory intentionally excludes itself to avoid a digest cycle. When inputs change, retain the prior inventory with its evidence and regenerate a new one using `install/prepare_source.py`. The generated installation pins its own new closure; it does not mutate the original frozen runtime.

Use the commands and scope in [Assurance](docs/ASSURANCE.md). Historical tests with frozen runtime dependencies are retained as source; do not silently retarget them to a new bundle and describe that as the original campaign. New installation controls use fresh packages generated by the installed decoder.

Compiler warnings are errors. Runtime assertions remain enabled. A failed proof or adversarial control is a result to investigate and retain, not an obstacle to remove from the gate.
