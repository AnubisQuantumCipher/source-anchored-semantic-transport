# Prepare new records for transport and replay

`install/prepare_quorum_sender.py` accepts your QUORUM records and pinned source
files, encodes a matching share text and meaning ZIP, and prepares two recipient
commands. One reads the originals; the other recovers the same records from the
ZIP. Both use the existing qualified checker. No expected verdict is supplied to
the sender or copied from a demonstration.

The [multilingual ferry example](../examples/quorum-sender-v1/input-template.json)
preserves a reservation condition, safety exception and uncertain weather status.
Its separate timetable revision marks a declared context dependency as needing revalidation even
though the notice quotation is unchanged. The example's full expected results
were written before the adapter, then compared with actual recipient executions.

## Inputs

Supply canonical JSON: UTF-8, sorted object keys, no whitespace between tokens,
no final newline, no floats, duplicate keys or nonfinite values. The sender input
has these fields only:

```json
{
  "schema": "quorum/sender-input/1",
  "body": {"path": "/absolute/body.json", "bytes": 0, "sha256": "<digest>"},
  "sources": [
    {"alias": "NOTICE", "path": "/absolute/notice.txt",
     "key": {"logical_source_id": "ferry.notice-v1", "bytes": 0, "sha256": "<digest>"}}
  ]
}
```

The zeros and digest placeholders illustrate field positions. Calculate actual
lengths and digests from your bytes. The Body uses the existing closed
[`quorum/replay-body/1` schema](../tools/transport_quorum_body.schema.json) and
[protocol](../tools/transport_quorum_protocol-rules.json). Author its readings,
source links and uncertainty explicitly. Preparation does not infer them.

Every Body source alias/key must appear exactly once in `sources`. An alias uses
`[A-Z][A-Z0-9_]{0,31}`; `Q_RECORDS` is reserved for the Body. Logical source IDs
retain the existing wire grammar, including its documented final-LF behavior.
There may be up to 15 supplied sources. Their combined bytes plus the Body must
fit 65,536 bytes. There must be exactly one task. File paths are absolute,
bounded, normalized and cannot traverse symlinks.

The independently held identities document has schema
`quorum/sender-held-identities/1` and these seven fields, each containing only
`bytes` and `sha256`:

- `bootstrap_entry`: approved replay bootstrap.
- `decoder_install_descriptor`: installed `INSTALL.json`.
- `runtime_descriptor`: installed `RUNTIME.json`.
- `source_manifest`: matching decoder source `install/SOURCE.json`.
- `bundle_snapshot`: approved installation snapshot, including modes.
- `encoder_launcher`: installed `bin/semantic-transport`.
- `sender_input`: the input document above.

Obtain runtime identities from the installation/release evidence you intend to
trust. Hashing whatever happens to be present does not authenticate it. This
adapter supports the already qualified launcher version; unsupported identities
fail closed. Its two preparation/presentation helper modules are pinned and
loaded from checked source bytes, without accepting bytecode caches.

## Encode and prepare

Replace uppercase paths with your actual approved paths. The output directory
must not exist.

```sh
python3 -I -S -B -Werror install/prepare_quorum_sender.py \
  --checker-root /CHECKER_SOURCE \
  --decoder-root /APPROVED_DECODER \
  --decoder-source-root /MATCHING_DECODER_SOURCE \
  --snapshot-file /APPROVED_SNAPSHOT.json \
  --held-identities /HELD_IDENTITIES.json \
  --sender-input /SENDER_INPUT.json \
  --out /NEW_OUTPUT \
  --budget 512 --reference attached:meaning.zip
```

The matching public artifacts are `encoded/share.txt`, `encoded/meaning.zip` and
`encoded/lexicon.md`. The character budget counts the complete canonical share,
including the STS1 identity, reference and newlines, as Unicode code points.
This is not a claim about a social platform's counting rules or public hosting.
The reference is data; no network request is made.

For the existing display-only public companion, use the
[presentation formatter](PUBLIC_SHARE.md):

```sh
python3 -I -S -B install/transport_public_share.py format \
  /NEW_OUTPUT/encoded/share.txt /NEW_OUTPUT/public-share.txt --budget 512
```

That companion has its own complete character-budget check. Supply the canonical
share and ZIP to the decoder. The display token establishes no authorship.

Preparation also creates a plan, exact original copies, an original-source index,
a checker descriptor, and separate `original-*` / `transport-*` requests,
envelopes, invocations and commands. `preparation-receipt.json` says
`PREPARED_NOT_EXECUTED`: the encoder ran, but the replay commands did not. Full
record/schema/reference validation belongs to that later checker execution.
No `expected.json` is generated by the product.

After independently checking the approved bootstrap and generated invocation
pins, execute `transport-command.txt` using the declared local dependencies.
The corresponding JSON contains the argv for shell-free callers. These command
files are sender-side tooling artifacts, not instructions loaded from the ZIP.
The transport invocation deliberately refers to absent original/Body sidecars;
those bytes must come from the package. `original-command.txt` is the matched
baseline using identical annotations and the same checker.

On failure the command exits nonzero with `REFUSED_SENDER_PREPARATION` and a
named reason. Invalid inputs are rejected before creating the output directory.
Failures after encoding can leave a new partial directory with encoder evidence;
absence of a successful final preparation receipt means preparation did not
finish. Existing directories are never overwritten. Keep failure evidence and
choose a fresh output path for another attempt.

## Compatibility and scope

This adapter reuses the existing exact-byte carrier. Its historical outer labels
say `Exact fixture ...`, and its outer interpretation/relation lists are empty.
Those labels do not certify a source or replace provenance inside `Q_RECORDS`.
Actual typed claims, declarations, qualifications and dependencies remain in the
recovered Body. This version does not import arbitrary pre-existing meaning ZIPs
or make the generic overview display every declared relationship.

An exact quotation match can coexist with an unsupported interpretation and a
dependency requiring revalidation. Current authority remains `NONE`; source
authentication is unverified and offline freshness is unknown. The Python
adapter is tested, not formally proved. Existing native assurance and runtime
identities are unchanged.

## Reproduce the development evidence

```sh
python3 -I -S -B -Werror install/test_quorum_sender.py \
  --decoder-root /APPROVED_DECODER \
  --decoder-source-root /MATCHING_DECODER_SOURCE \
  --snapshot-file /APPROVED_SNAPSHOT.json \
  --host-identities /PRIOR_PUBLIC_HELD_IDENTITIES.json \
  --evidence /NEW_TEST_EVIDENCE
python3 -I -S -B examples/quorum-sender-v1/receipt.py --check
```

The host-identities file supplies the same five existing host pins listed above;
the harness pins each newly materialized test input and approved launcher. The
harness and qualified verification helper require inherited hard limits of at
least 120 CPU seconds and 33,554,432 file-size bytes. Their fixed child limits
cannot be raised above lower inherited hard limits. Captured stdout/stderr are
separately bounded; these per-process limits do not imply aggregate isolation.
The
harness runs normal and optimized Python, retains first streams, compares full
results against independent literal oracles and byte-compares every recovery.
It removes original-arm sidecars before ZIP replay. Negative controls cover
alias closure, changed bytes, incompatible versions, resource/task bounds and
existing outputs. Additional valid identifier cases preserve wire compatibility.

The published receipt retains an initial harness failure: incorrectly lowered
inherited hard limits prevented the existing verification child from launching.
The fix preserves the qualified helper's existing limits and bounds captured
streams separately. It also retains the review finding and correction for
logical IDs being mistakenly restricted to the archive-alias grammar.

The local observations use Linux aarch64 and Python 3.14.7 with the exact pinned
installed decoder. Portable receipt checks on CI do not exercise that installation
or establish x86, desktop-client or marketplace acceptance. A fresh receiving
agent reconstructed the development package; a separate source evaluator scored
it against criteria frozen before that run. This is qualitative development
evidence, not an external-user study or measured improvement over originals.
