# An obligation checked against a proposed patch

The decoder can now connect a source-bound predicate to a finite test of an
exact proposed function replacement. It recomputes every declared input state,
records counterexamples, and passes the result to the existing SPARK obligation
evaluator. A received success receipt is accepted only when fresh computation
reproduces it. Candidate code is interpreted through a bounded whitelist as data.

This fixture keeps the original coding requirement, correction, revoked approval,
conflicting reports and unfinished actions. It adds a named proposition for the
complete corrected condition and a separately pinned expected table. The earlier,
more detailed interpretation stays intact, including its unsupported operators
and uncertainty; evaluation does not silently replace it.

## Use it

The matched outputs are [share text](share.txt), [meaning ZIP](meaning.zip), and
[readable lexicon and operator definitions](lexicon.md). The six text files and
[authoring plan](plan.json) are also included. Reproduction commands and the test
receipt schema are in [Bound tests](../../docs/BOUND_TESTS.md).

The committed ZIP requires its exact recorded decoder runtime. Rebuild and
re-encode with your own trusted installation to obtain a package for that
runtime. The native binaries are separately identified dependencies, not included
in this example or the selected evidence archive.

```sh
python3 -I -S -B -Werror install/test_finite_check.py
python3 -I -S -B -Werror install/test_bound_test_receipts.py \
  --bundle /absolute/installed/decoder \
  --native /absolute/transport_bound_eval_native \
  --evidence /absolute/new/evidence-directory
```

The [selected evidence](evidence.zip) and [export receipt](../../receipts/bound-tests-1.json)
retain source identities, test captures, first drafts, fixed criteria, exact
dispatches, selected tool traces and review results. The archive is a bounded
selection. Capture groups preserve their exact contents and nested hashes;
explicitly marked metadata maps host paths.

## What passed, and what did not

| Check | Observed result |
| --- | --- |
| Finite checker unit suite | 21 tests passed |
| Existing expression interpreter suite | 20 tests passed |
| Actual decoder and native integration | 13 tests passed; 23 bounded subprocesses; no skips |
| Original source recovery | All six source entries compared byte for byte |
| Incorrect candidate controls | Wrong actor, boundary error and overbroad exception produced `VIOLATED` |
| Invalid evidence controls | Forged, swapped and truncated receipts; altered pins; unsafe syntax; excessive domain refused |
| Fresh original-document recipient | First submitted patch passed all 480 declared states and 22 source checks |
| Fresh transport recipient | First submitted patch passed the same states and source checks; optional recomputed test passed |
| Comparative benefit | **Tie on the observed task; no advantage demonstrated** |

Both recipients preserved historical verification as `UNKNOWN`, the revoked
approval, absent current publication approval, and recorded pending actions.
The transport recipient kept the new test result separate from those historical
records. A separate source evaluator checked narrative fidelity and submission
custody against criteria fixed before dispatch. Both recipients used fresh
contexts with only the declared interfaces and dependencies, on a shared host.
Observed model identifiers were `gpt-6.1-sol`, reasoning `high`.

The original arm had the same six sources, task and response contract. The
transport arm additionally had declared readings and the finite-check tool.
This compares workflows with different capabilities; it does not isolate the
effect of packaging. There was one first candidate per arm. Native compaction,
cross-model transfer and external-user acceptance were not run in this case.

The first integration attempt failed during fixture setup before decoder or
native execution. Its original receipt mistakenly carried hardcoded execution
labels. Both that failure and the explicit correcting addendum are retained;
the successful run records observed execution. No failure was overwritten.
The evaluator's repaired raw-versus-canonical digest assertion is retained too;
it did not change either candidate or the fixed criteria.

## Cost observed in this case

| Artifact | Bytes |
| --- | ---: |
| Original six sources | 5,364 |
| Ordinary gzip of concatenated sources | 2,218 |
| Explicit authoring plan | 12,723 |
| Complete share text | 1,239 |
| Meaning ZIP | 103,095 |
| Separate readable lexicon, also included inside ZIP | 56,363 |

The complete share has 1,238 Unicode code points, including identity and package
reference. It does not fit a 200-character post. Keeping the detailed visible
relations incurs this cost; no platform-specific counting rule was tested.

Both readers made nine calls. Recorded reader response bytes were 18,515 for the
original arm and 28,008 for transport. Host cumulative counters reported 384,887
and 469,395 total tokens respectively. These counters include global instructions
and repeated context; they are not document-only token counts or billed costs.
Exact timestamps, process latency observations and captured tool-output byte
counts are retained in the evidence. No speed, cost or context saving is claimed.

Shared dependencies remain separate: the installed decoder contains 1,943,944
file bytes; the evaluator executable is 1,488,368 bytes. The two new Python
modules total 14,334 bytes, within a local import closure of 116,698 bytes.
Python, its standard library, system libraries and OS are additional dependencies.
The complete package loses the storage comparison with plain source and gzip.

## Assurance boundary and next acceptance

The existing SPARK evaluator and its proof source bytes are unchanged. This
addition's Python checker and integration are tested, not formally proved.
Matching an explicit finite table does not prove that the table captures English
meaning, that the domain is sufficient, or that the source is true. Source
material and opaque historical records remain in the package, with unresolved
intervals and uncertainty visible. No decoded obligation grants execution
authority.

The next comparative acceptance needs held-out continuation tasks and repeated
handoffs with outcomes fixed before dispatch. It must retain the original-text
baseline and measure errors and costs, including ties and cases transport loses.
The current implementation supplies a working test binding for that comparison;
external validation and general semantic superiority remain open.
